CopperSFS 1.0 - runtime-control qualification
============================================

This experimental package contains one configurable 68020+ handler and the
CopperSFSCtrl command. The reference is 68k SmartFilesystem 1.279 from Joerg
Strohmayer's development branch; SFS was originally developed by John Hendrikx.
The exact shipped executable hashes and compiler revision are in RELEASE.json.

The shipped buffered-default handler passed all 13 selected A/B cases and
a separate memory measurement. A strict-initial qualification build passed
seven selected cases; that build is not shipped. Coverage includes shared
handles/positions, concurrent writers/readers, metadata, directories, timer
checkpoints, clean remounts, both clean handoff directions and original TRST
replay. Independent amidisk extraction and deep consistency checks passed.

All 329 unsampled interruption/reboot cases passed: 98 buffered CopperSFS,
107 strict-initial CopperSFS, and 62 reference cases repeated in each
comparison. Create, overwrite, truncate, rename and delete were interrupted
after every relevant sector write or flush, including sectors inside combined
requests. Each image was recovered by its writing handler. Original-handler
results are observations against its own behavior; CopperSFS old-or-new
assertions do not strengthen the reference handler's contract.

The shipped handler also passed all 40 distinct sector-write/flush cuts in
a mode-switch checkpoint, with absent-or-complete new file recovery. Native
CLI/configuration/concurrent-I/O tests passed from both initial modes, with
fresh remount and independent checks. Seventeen compiled MC68000 control
cases cover allocation/timer/checkpoint failures, resource ordering and
I/O-free query/resize. Core semantics passed 203 tests; one optional external
image case was skipped. Host, compiled instruction and native OS tests are
different coverage. No failed case or disk-operation index was recorded.

All sector-read/write and device-request/flush counts match the preceding
clean-cache build. Requests count reads, writes and flushes, not sectors.
CopperSFS still writes more sectors in some workloads than reference SFS.
Raw counts and interruption indices are retained in the qualification report.
These are emulated CPU/I/O measurements, not physical transfer rates.
Strict mode has no performance claim.

Separate 64 KiB working set, five cold and five warm trials per handler:
Handler                  Cold / warm cycles       Cold / warm requests
Original                  677,140 /  696,641    8 /  8
CopperSFS                 317,160 /  609,271   16 /  0
CopperSFS-before-cache    320,899 /  306,630   16 / 16

Warm trials follow two admission passes. The clean cache removes warm device
requests, but RAM copying costs more guest CPU than prior direct emulated I/O.
Large sequential streams bypass the pool. Comparisons are not normalized to
equal total memory. Default loaded + mounted RAM is 585,480 bytes, an increase
of 1,344 bytes over the preceding build. INFO reports live pool/buffer sizes.
Explicit runtime resize failure retains the old pool. Disable/128K/256K live
changes and simulated 512K allocation/failure were tested; full 2M allocation
remains unqualified. See INSTALL.txt for valid capacities and startup settings.

Profile: Kickstart 3.1, 68020, 512 KiB chip, 2 MiB fast, 512 KiB slow RAM,
32 mount buffers, 512-byte sectors. Every run starts from its own fresh clone
of the same immutable 16 MiB base image. Geometry: two surfaces, 32 blocks per
track, cylinders 0-511, two reserved blocks, offset zero. Mask 0x7FFFFFFF,
MaxTransfer 0x1FE00. Boot/image-copy time excluded. This is test geometry.

The crash model assumes atomic 512-byte sectors, honored ordered flushes
and loss of unflushed writes. Torn sectors, reordered/dishonest controllers,
physical hardware and other ROM configurations are outside qualification.
Never expose an unresolved CSUN transaction to another SFS handler. Native
device access beyond 4 GiB remains unqualified; TD64 is required and NSD is
not supported. The handler uses classic 32-bit DOS file sizes/seek positions.
